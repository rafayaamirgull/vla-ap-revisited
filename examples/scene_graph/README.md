# 3D scene graph from the wrist RGB-D camera

This step turns a MuJoCo wrist capture and its YOLO-World/SAM2 detection report into an instance graph in world coordinates. Each accepted object has a masked 3D point cloud, observed centroid and bounds, and a CLIP ViT-B/32 image embedding. Edges describe geometric `on`, `next_to`, and, when a container interior is supplied, `inside` relations.

## Run one frame

Use the Docker container and dependencies described in the [main README](../../README.md). Capture and process a **new** frame so the camera metadata and detection report contain RGB-D fingerprints:

```bash
docker exec vla_scenegraph_env /root/miniconda3/bin/python \
  /workspace/examples/ur5e_eye_in_hand/run.py --frames 1 --seed 7 --hb-count 3

docker exec vla_scenegraph_env /root/miniconda3/bin/python \
  /workspace/examples/open_vocab_pipeline/run.py \
  --prompts "red cube, green bell pepper, toy car" --confidence 0.005

docker exec vla_scenegraph_env /root/miniconda3/bin/python \
  /workspace/examples/scene_graph/run.py
```

The first run of CLIP downloads its ViT-B/32 checkpoint into `/root/.cache/clip/` in the container. The [perception guide](../open_vocab_pipeline/README.md) shows how to keep this cache across container restarts. If HomebrewedDB is not mounted, the simulator captures only the cube and the graph still runs. A prompt that matches no visible object can produce zero detections.

The graph step reads `outputs/open_vocab_pipeline/frame_0000_detections.json` by default and writes these files under `outputs/scene_graph/`:

| File | Contents |
| --- | --- |
| `frame_0000_scene_graph.json` | Camera transform, provenance, nodes, relations, thresholds, and rejected detections. |
| `frame_0000_points.npz` | One world XYZ and RGB array per accepted instance. |
| `frame_0000_object_XX_clip_crop.png` | The image region used for that instance's CLIP embedding. |
| `frame_0000_scene_graph.png` | Local 3D view beside the relation graph. |

Process all detection reports in one directory with `--detections /workspace/outputs/open_vocab_pipeline --frames 0`. Use a separate `--output-dir` for each experiment: `frame_0000` names are reused by different captures, and rerunning into the same output directory replaces earlier results. `--no-plot` skips the PNG. Use `--device cpu` if CUDA is unavailable.

If you used the seed 1 prompt experiment in the [perception guide](../open_vocab_pipeline/README.md), pass its report explicitly:

```bash
docker exec vla_scenegraph_env /root/miniconda3/bin/python \
  /workspace/examples/scene_graph/run.py \
  --detections /workspace/outputs/seed1_perception/frame_0000_detections.json \
  --output-dir /workspace/outputs/seed1_graph
```

## Geometry and frame convention

MuJoCo renders axial depth in meters. For a valid masked pixel `(u, v)` with depth `z`, the code uses the pixel center and camera intrinsics to form

```text
p_camera = [((u + 0.5) - cx) * z / fx,
            ((v + 0.5) - cy) * z / fy,
            z]

T_world_camera = T_world_base @ T_base_ee @ T_ee_camera_optical
p_world = T_world_camera @ [p_camera, 1]
```

The optical frame points right, down, and forward. The MuJoCo world frame is in meters. `T_world_base` matters because the UR5e base is translated and rotated in this scene. Each fresh capture records the full chain and the direct camera pose; the graph code checks that they agree. It also checks RGB, depth, and mask hashes before using them. Reports from older captures without the fingerprints must be regenerated by repeating capture and perception.

For each mask, invalid and out-of-range depth is discarded. Masks touching the image edge are excluded by default, including if they came from an older perception report; use `--allow-border-masks` to keep incomplete views. Points are grouped in metric voxels, connected within `--cluster-radius` (default 2.5 cm), and the largest component with at least `--min-points` (default 80) is retained. The point cloud is capped by `--max-pixels` (default 30,000) for clustering; the CLIP crop recovers full-resolution mask pixels that lie near the retained 3D component. Each node's bounds are the 2nd to 98th percentile of **observed** points, and its centroid is their coordinate-wise median. These are visible-surface measurements, not a full object shape or a 6D pose.

The graph keeps the detector's label as a prompt-conditioned candidate. It also compares the instance crop with every supplied text prompt and records CLIP's top prompt and its cosine margin over the runner-up. A margin below `--clip-margin` (default 0.04), or disagreement with the detector label, marks `semantic_status` as `ambiguous_within_prompts` and adds `?` in the plot. A larger margin only means the label is more distinct **among the supplied prompts**; it does not prove the physical object's identity. Include plausible alternatives in the prompt set.

## Relation rules

| Edge | When it is emitted |
| --- | --- |
| `object on support` | The observed object bottom is within 2.5 cm above the support top, or at least 20 connected visible points lie within 3 cm above the known table plane. XY bounds must overlap. The table support is a known static MuJoCo geom, marked as such in the graph. |
| `object next_to object` | Their observed XY bounds are within 8 cm, their median heights are similar, and they do not overlap or already have an `on` relation. This edge is symmetric and stored once. |
| `object inside container` | The object's observed bounds fit inside an explicitly supplied interior world AABB. |

The default tabletop scene has no calibrated container interior, so it normally emits no `inside` edge. To test a container, create a JSON file mapping a detected container ID to its measured **interior** bounds in world meters, then pass `--interiors /workspace/path/to/interiors.json`. For example, replace these illustrative numbers with the actual cavity bounds for the current frame:

```json
{
  "object_02": {"min": [0.20, 0.30, 0.27], "max": [0.36, 0.46, 0.38]}
}
```

Instance IDs are assigned per frame from detection order; there is no temporal tracking. A single wrist view cannot reliably reconstruct an unseen container interior, so `inside` is only asserted with this explicit prior. The connected contact patch helps recover support when an overhead view hides most of an object's bottom, but a SAM mask leaking onto the table could create a false contact patch. All edges are geometric hypotheses with supporting measurements in the JSON, not calibrated probabilities. CLIP `text_cosine` values are likewise similarities, not detection confidence. Check the YOLO/SAM overlay before treating low-confidence labels as research annotations.
